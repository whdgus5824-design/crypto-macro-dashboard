## 📊 설계 핵심 원칙

### ❌ 해야 할 것들 (설계 단계)
```
1. "AI가 주문을 직접 하지 않도록" 구조화
   신호 → 위험관리 → 주문 (3단계)

2. 배종현님의 투자 원칙을 code로 명시
   각 규칙이 점수에 영향을 미치도록 설계

3. 점수에 "이유"를 항상 포함
   "점수 87점: 추세 양호(+20), 거래량 증가(+15)"

4. 수익률만 보지 말고 MDD도 중시
   백테스트: 100% 수익 but 70% MDD는 나쁜 전략

5. 점진적 자동화
   수동 검증 → 스캐너 → 백테스트 → 모의 → 자동매매
```

### ✅ 금지 사항
```
❌ API 키를 코드에 직접 입력
   → 환경변수 (.env) 사용

❌ 단일 거래소에 의존
   → 주식 + 크립토 + (나중에 선물) 통합

❌ 과도한 자동화 처음부터
   → 데이터 검증 먼저

❌ 손절 기준 없이 매매
   → 반드시 구현
```

## 💡 핵심 아이디어

### "스캐너가 중심이다"
```
자동매매 ← 스캐너 + 위험관리 + 주문 실행
          ← (가장 중요한 부분)

스캐너만 완성되면:
- 수동 거래 시 참고 가능
- 백테스트로 검증 가능
- 나중에 주문 모듈만 추가
```

### "점수에는 이유가 있다"
```
❌ "ETH가 좋습니다" (X)
✅ "ETH는 추세 양호(+20), OI 증가(+5)이나
    Funding이 과열되어 신규진입 신중"
```

### "규칙이 판단을 결정한다"
```
AI 의견 X
시스템 규칙 O

→ 재현 가능 / 감정 배제 / 검증 가능
```
